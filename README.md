# רשימת גריטה – אפליקציה חיצונית

אפליקציית ווב לאיסוף ציוד לגריטה: סריקת סיריאלי ומרכבה, קטלוג דגמים שמשלים אוטומטית, תמונות, וייצוא לאקסל.
רצה בחינם על **GitHub Pages**, עם התחברות ושמירה בענן ב-**Firebase** (התוכנית החינמית Spark, בלי כרטיס אשראי).

- כל משתמש מקבל **רשימה אישית** שרק הוא רואה, מכל מכשיר.
- **רשימת צוות** משותפת – רק למנהלים ולחברי צוות שמנהל הוסיף ב"ניהול צוות".
- אפשר להתקין כאפליקציה בטלפון, והיא עובדת גם בלי קליטה (מסתנכרנת כשהקליטה חוזרת).

## קבצים

| קובץ | מה זה |
|---|---|
| `index.html` | האפליקציה |
| `config.js` | **הקובץ היחיד שצריך לערוך** – פרטי Firebase ומייל המנהל |
| `firebase-adapter.js` | חיבור ל-Firebase ומסך ההתחברות |
| `firestore.rules` | כללי האבטחה – מדביקים ב-Firebase |
| `manifest.webmanifest`, `sw.js`, `icons/` | התקנה כאפליקציה ועבודה בלי קליטה |

## הקמה (פעם אחת, כ-20 דקות)

### 1. Firebase
1. [console.firebase.google.com](https://console.firebase.google.com) ← **Create a project** (אפשר לכבות Analytics).
2. **Build ← Authentication ← Get started ← Sign-in method**: הפעל **Google** ו-**Email/Password**.
3. **Build ← Firestore Database ← Create database**: מיקום **me-west1 (Tel Aviv)**, מצב **production**.
4. **Firestore ← Rules**: מחק את מה שיש, הדבק את כל התוכן של `firestore.rules` ולחץ **Publish**.
   את `OWNER_UID` מחליפים אחרי ההתחברות הראשונה (שלב 5 למטה).
5. גלגל השיניים ← **Project settings ← Your apps ← `</>`** (אפליקציית ווב) ← העתק את `firebaseConfig`.

### 2. config.js
פתח את `config.js` והדבק את הערכים מ-`firebaseConfig` במקום `PASTE…`.
הערכים האלה **לא סודיים** – ההגנה על הנתונים היא בכללי האבטחה. **אין בקוד שום מייל.**

### 3. GitHub Pages
1. העלה את כל הקבצים (כולל התיקייה `icons` והקובץ `.nojekyll`) לשורש מאגר **ציבורי** ב-GitHub.
2. במאגר: **Settings ← Pages ← Build and deployment ← Deploy from a branch ← main / (root) ← Save**.
3. אחרי דקה-שתיים האתר זמין ב: `https://<שם-המשתמש>.github.io/<שם-המאגר>/`

### 4. אישור הכתובת ב-Firebase
**Authentication ← Settings ← Authorized domains ← Add domain** ← `<שם-המשתמש>.github.io`
(בלי זה ההתחברות עם גוגל תיכשל עם הודעה על כתובת לא מאושרת).

### 5. החשבון הראשי ומנהלים
1. התחבר לאתר פעם אחת.
2. ב-Firebase: **Authentication ← Users** – העתק את ה-**User UID** שלך (מזהה אנונימי, לא מייל).
3. **Firestore ← Rules**: החלף את `OWNER_UID` ב-UID שהעתקת ← **Publish**.
4. מעכשיו אתה החשבון הראשי. ב-**ניהול צוות** מוסיפים **מנהלים** (בדיוק כמוך: רואים הכל ומנהלים את הצוות)
   ו**חברי צוות** (רואים ועורכים את רשימת הצוות).
עובד שנרשם עם מייל וסיסמה צריך ללחוץ על קישור האימות שנשלח אליו לפני שיראה את רשימת הצוות.
כל אחד, גם בלי להיות בצוות, יכול להתחבר ולעבוד ברשימה האישית שלו.

## התקנה בטלפון
- **אנדרואיד (Chrome):** תפריט ⋮ ← "התקנת אפליקציה" (או הכפתור "התקן את האפליקציה עכשיו" בחלון "פתיחה והתקנה בנייד").
- **אייפון (Safari):** כפתור השיתוף ← "הוספה למסך הבית".

## עלויות ומגבלות (התוכנית החינמית)
- Firestore בחינם: עד 1GB נתונים, 50,000 קריאות ו-20,000 כתיבות ביום – הרבה מעבר לרשימות כאלה.
- התמונות נשמרות דחוסות בתוך Firestore (עד ~0.7MB לתמונה), כך שלא צריך את Cloud Storage, שדורש תוכנית בתשלום.
  בערך 1,500–3,000 תמונות נכנסות במכסה החינמית. אם מגיעים לשם – מוחקים רשימות ישנות אחרי ייצוא לאקסל.
- Firebase לא יחייב אתכם בלי שתעברו בעצמכם לתוכנית Blaze ותוסיפו כרטיס אשראי.

## אבטחה ופרטיות
- רשימה אישית: רק בעל החשבון קורא וכותב (`data/users/{uid}`).
- רשימת צוות: רק מנהלים וחברי צוות עם מייל מאומת.
- רשימת המנהלים וחברי הצוות (`config/access`) גלויה **רק למנהלים**.
- החשבון הראשי מזוהה רק לפי UID בכללי האבטחה – המייל שלו לא מופיע בקוד, במאגר או בבסיס הנתונים.
- כל משתמש רואה באפליקציה רק את המייל של עצמו.
- הכללים בודקים גם מבנה וגודל של כל פריט ותמונה ברשימת הצוות, וחוסמים כל נתיב אחר.
- מומלץ (לא חובה): ב-Google Cloud Console ← APIs & Services ← Credentials, להגביל את מפתח ה-API לכתובת האתר שלכם.

## עדכון גרסה
מחליפים את הקבצים במאגר (בלי `config.js`, אם כבר מילאתם אותו). אחרי העדכון, האפליקציה בטלפונים מתעדכנת בפתיחה הבאה עם קליטה.
